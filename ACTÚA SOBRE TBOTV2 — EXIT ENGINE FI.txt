==================================================
1. PROBLEMA ACTUAL
==================================================

La estrategia actual está diseñada para:

ENTRY
→ si el precio va en la dirección esperada
→ dejar correr la posición
→ NO cerrar prematuramente por un TP pequeño
→ detectar debilitamiento/reversión
→ salir cuando exista evidencia razonable de que la tendencia favorable está terminando.

Actualmente observamos este comportamiento:

LONG:
entry
→ precio sube y alcanza profit significativo
→ posteriormente empieza a caer
→ el sistema no reconoce a tiempo el cambio de tendencia
→ devuelve gran parte o todo el profit
→ puede terminar en SL

También ocurre:

entry
→ precio sube
→ después baja
→ no toca SL
→ no genera suficiente trend_fade
→ no existe time-stop efectivo
→ posición permanece abierta durante horas.

Esto NO es el comportamiento deseado.

==================================================
5. SEPARAR TRES CONCEPTOS
==================================================

El sistema debe distinguir:

A) TREND WEAKENING
La tendencia favorable pierde fuerza.

B) TREND REVERSAL
Existe evidencia suficiente de que la dirección favorable está terminando.

C) STALE POSITION
La operación permanece abierta demasiado tiempo sin progreso suficiente.

No deben ser tratados como el mismo evento.

==================================================
6. NUEVA LÓGICA DE EXIT
==================================================

Implementar una salida adaptativa.

LONG:

1. Mientras el precio continúa haciendo progreso favorable:
   → HOLD.

2. Registrar continuamente:
   - highest favorable price desde entry
   - MFE
   - current profit
   - drawdown desde peak
   - tiempo desde entry
   - tiempo desde último nuevo favorable extreme.

3. Detectar weakening antes de exigir reversal completo.

4. Si existe profit significativo y empieza un deterioro:
   → activar protección de profit.

5. Si aparece reversal suficientemente confirmado:
   → EXIT.

SHORT:
implementar exactamente lo mismo de forma simétrica.

==================================================
7. PEAK PROFIT / GIVEBACK PROTECTION
==================================================

Añadir una capa de protección basada en el máximo favorable alcanzado.

Conceptualmente:

LONG:

entry
→ MFE +0.10%
→ MFE +0.30%
→ MFE +0.60%
→ MFE +1.00%

Si posteriormente el precio devuelve una cantidad configurable del MFE:

peak profit = +1.00%
current profit = +0.65%

giveback = 35% del MFE

Esto NO debe cerrar inmediatamente.

Debe combinarse con weakening/reversal.

Ejemplo:

MFE = +1.00%
giveback = 10%
→ probablemente HOLD

MFE = +1.00%
giveback = 30%
+ momentum deterioration
→ posible exit

MFE = +1.00%
giveback = 40–50%
+ reversal confirmation
→ EXIT

Los thresholds deben ser CONFIGURABLES.

NO optimizarlos automáticamente en esta etapa.

No asumir valores mágicos.

11. STALE POSITION / MAXIMUM DURATION
==================================================

Actualmente `max_hold_minutes` parece ser metadata y NO un time-stop efectivo.

Eso es peligroso para una estrategia diseñada para operaciones de minutos.

NO quiero volver al antiguo comportamiento de cerrar automáticamente cada 5–10 minutos.

Pero sí quiero un safety timeout configurable.

Añadir:

`stale_position_max_minutes`

como límite de seguridad.

No debe ser un TP.

No debe cerrar automáticamente todos los trades al alcanzar ese tiempo.

Debe evaluar:

- profit actual
- MFE
- tiempo desde último nuevo favorable extreme
- trend state
- momentum
- drawdown desde MFE.

Conceptualmente:

Si:

trade_duration > stale_position_max_minutes
AND
no meaningful favorable progress recently
AND
trend is no longer strongly favorable

→ EXIT por `stale_position`.

Pero:

si la posición sigue haciendo nuevos highs/lows favorables
→ permitir HOLD.

Esto evita posiciones abiertas durante horas sin destruir operaciones que siguen tendiendo correctamente.

maximum_trade_duration sera de 60 min, y SOLO como emergency/stale-position exit, no como TP.
Será así:
1–10 min
→ estrategia normal

10–30 min
→ seguir si está progresando

30–60 min
→ exigir evidencia fuerte de continuación

>60 min
→ cerrar por stale trade
